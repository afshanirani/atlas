# Initiatives

Active workstreams beneath the products. This file turns over faster than the others —
structure can sync from the ticketing system; the *why* and the *blocked-on* cannot.

`last_verified: TODO`

## Template

```
## <Initiative>

- **Part of:** [[product]]
- **Goal:** what changes if this succeeds
- **Status:** not started | in progress | blocked | shipped | parked
- **Blocked by:** person, decision, dependency, or access — be specific
- **Deadline type:** locked (external commitment) | soft (internal target) | none
- **Key decisions made:** decision, date, and *why* — especially options rejected
- **Open questions:** 
- **Skills implicated:** [[skill]] links
- **last_verified:** YYYY-MM-DD
```

## Notes

- **"Blocked by" is the highest-value field.** It's the answer to the most common real
  question — "what do I need to unstick?" — and no system captures it automatically.
- **Record rejected options, not just decisions.** The reason an approach was ruled out
  is what stops it being re-proposed every quarter.
- **Deadline type drives prioritization.** Locked always outranks soft, regardless of
  stated priority. Mark it honestly.
